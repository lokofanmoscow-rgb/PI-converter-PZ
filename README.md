# ПИ → ПЗ конвертер (ИЛ ООО «Астра»)

Десктопная программа для Windows: берёт протокол испытаний (ПИ, `.docx`) и создаёт
технические (первичные) записи (ПЗ, `.docx`) по шаблону `ПЗ_template.docx`.

## Как пользоваться

1. Запустите `PI_to_PZ.exe`.
2. «Выбрать ПИ (.docx)» → укажите файл ПИ (можно просто перетащить файл ПИ на значок программы).
3. «Создать ПЗ». Готовый файл `ПЗ_{НОМЕР}_от_{ДД_ММ_ГГГГ}.docx` появится в той же папке, что и ПИ.
4. «Открыть папку с результатом».

В окне программы выводится сводка (номер ПИ, направление, образец, даты, условия,
число компонентов и фото) и предупреждения — их стоит прочитать.

Нужен именно `.docx` ПИ: в отсканированном PDF первые страницы — картинки, данные из них не извлекаются.

## Что делает программа

**Из ПИ берётся:** номер и дата (`№ XXXXXXX от ДД.ММ.ГГГГ`), направление, дата/время испытаний,
номер комнаты, наименование и шифр образца, условия (Таблица №1), оборудование (Таблица №2),
результаты по компонентам (таблица с `w:vMerge`), фото и подписи из Приложения №1.

**В ПЗ заполняется:**

- шапка: направление, образец + шифр, «с … по …», условия (диапазоны как в ПИ), комната;
- строка пробоподготовки: наименование образца, число компонентов, дата/время и условия начала;
- блоки компонентов — столько, сколько в ПИ (строятся по образцу строки из шаблона, ограничения в 51 блок нет):
  - условия интерполируются от min к max по номеру компонента, последний = max;
    точность — как в ПИ (`101,4` → 1 знак), давление в гПа = кПа × 10 с на один знак меньше
    (`101,4` → `1014 (101,4 кПа)`, `98,67` → `986,7 (98,67 кПа)`);
  - дата: компонент 1 — дата + время начала, последний — дата + время окончания, остальные — только дата;
    при испытаниях в несколько дней компоненты делятся по дням пропорционально минутам,
    последний компонент дня получает время конца дня, первый компонент следующего дня — время начала;
  - BL: «менее 10 мг/кг (0,001 %)» и строка `3σ < {sigma}`, где sigma = `random.seed(номер ПИ)`,
    `randint(3, 29)` по порядку компонентов и элементов (числовые результаты случайное число не расходуют);
  - числовой результат: «163 ± 21 мг/кг (0,0163 ± 0,0021 %)», `3σ = 21`, перевод в проценты;
- таблица оборудования — набор Б (если в ПИ у того же прибора другая дата поверки — берётся дата из ПИ, с предупреждением);
- даты подписей = дата ПИ;
- Приложение №1: по одной таблице на каждое фото ПИ (картинка копируется из ПИ, подпись — как в ПИ),
  «Приложение № 1 на N страницах» (одно фото на страницу);
- колонтитул: `№ {номер направления} от {дата направления}`, «Общее количество страниц» — поле Word (считается автоматически).

## Настройки

В начале `converter.py`:

| Параметр | Что задаёт |
|---|---|
| `EQUIPMENT_SET_B` | оборудование набора Б |
| `WORKDAY_START`, `WORKDAY_END` | рабочий день (09:00–18:00) для многодневных испытаний вида «ДД1 с ЧЧ:ММ по ДД2 ЧЧ:ММ» |
| `HEADER_NUMBER_SOURCE` | что писать в колонтитуле: `"napravlenie"` или `"pi"` |
| `PHOTO_MAX_W`, `PHOTO_MAX_H` | максимальный размер фото в приложении |

Шаблон можно заменить без пересборки: положите свой `ПЗ_template.docx` рядом с `PI_to_PZ.exe` —
программа возьмёт его вместо встроенного. В шаблоне должны быть: таблица «Основание проведения испытаний»,
таблица компонентов со строкой «Пробоподготовка» и хотя бы одной строкой «Содержание в компоненте N:»,
таблица оборудования, подписи, «Приложение №1» с таблицей «Фото №…».
Чтобы сделать шаблон из готового ПЗ: `python tools/make_template.py ПЗ_xxx.docx ПЗ_template.docx`.

## Сборка EXE

На Windows с Python 3.11+:

```bat
build.bat
```

Скрипт ставит `lxml` и `pyinstaller` и выполняет
`pyinstaller --onefile --windowed --add-data "ПЗ_template.docx;." --name "PI_to_PZ" main.py`.
Результат — `dist\PI_to_PZ.exe`.

EXE также собирается автоматически в GitHub Actions (`.github/workflows/build-exe.yml`) при каждом push:
тесты → `build.bat` → проверка EXE на тестовом ПИ → артефакт `PI_to_PZ` во вкладке Actions.

## Запуск без EXE

```bash
pip install lxml
python main.py                                   # окно
python converter.py ПИ.docx [шаблон] [папка]     # из командной строки
```

## Тесты

```bash
python -m unittest discover -s tests -v
```

`tests/fixtures/pi_2610101.json` — данные ПИ 2610101 и эталонный ПЗ; `tests/make_sample_pi.py` собирает из них
ПИ в формате Word, после чего результат сверяется с эталоном по всем 173 блокам (даты, условия, σ, результаты),
а также проверяются многодневные испытания, давление с двумя знаками, ПИ без фото, разрыв таблицы компонентов.

## Файлы

```

converter.py          извлечение данных из ПИ и генерация ПЗ (lxml)
ПЗ_template.docx      шаблон ПЗ (встраивается в EXE)
build.bat             сборка EXE
tools/make_template.py  сделать шаблон из готового ПЗ
tests/                тесты и тестовые данные
```

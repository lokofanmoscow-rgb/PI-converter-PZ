# ПИ → ПЗ конвертер (ИЛ ООО «Астра»)

Десктопная программа для Windows: берёт протокол испытаний (ПИ, `.docx`) и создаёт
технические (первичные) записи (ПЗ, `.docx`) по шаблону `ПЗ_template.docx`.

## Как пользоваться

1. Запустите `PI_to_PZ.exe`.
2. «Выбрать ПИ (.docx)» → укажите файл ПИ (можно просто перетащить файл ПИ на значок программы).
3. «Создать ПЗ». Готовый файл `ПЗ_{НОМЕР}_от_{ДД_ММ_ГГГГ}.docx` появится в той же папке, что и ПИ.
4. «Открыть папку с результатом».

В окне программы выводится сводка (номер ПИ, направление, образец, даты, условия,
число компонентов и фото) и предупреждения — их стоит прочитать.

Нужен именно `.docx` ПИ: в отсканированном PDF первые страницы — картинки, данные из них не извлекаются.

## Что делает программа

**Из ПИ берётся:** номер и дата (`№ XXXXXXX от ДД.ММ.ГГГГ`), направление, дата/время испытаний,
номер комнаты, наименование и шифр образца, условия (Таблица №1), оборудование (Таблица №2),
результаты по компонентам (таблица с `w:vMerge`, номер компонента может быть автонумерацией),
инженер-испытатель (блок «Испытания провел(а)» в конце ПИ), фото и подписи из Приложения №1.

**В ПЗ заполняется** (оформление — как в эталонном ПЗ 46ТР-НИ, из него сделан шаблон):

- шапка: направление, образец + шифр, «с … по …», условия (диапазоны как в ПИ), комната;
- строка пробоподготовки: наименование образца, число компонентов, дата/время начала и условия начала;
- блоки компонентов — столько, сколько в ПИ (строятся по образцу строки из шаблона):
  - время: компонент 1 — начало испытаний + 30 мин (пробоподготовка), последний — окончание − 5 мин,
    остальные — только дата; при испытаниях в несколько дней компоненты делятся по дням пропорционально минутам;
  - условия интерполируются от min к max по номеру компонента, последний = max;
    точность — как в ПИ, давление в гПа = кПа × 10 (`99,82` → `998,2 (99,82 кПа)`, `101,4` → `1014 (101,4 кПа)`);
  - BL: «менее 10 мг/кг (0,001 %)» и `3σ < {sigma}`, sigma = `random.seed(номер ПИ)`, `randint(3, 29)`
    по порядку компонентов и BL-элементов;
  - числовой результат: «74 ± 7 мг/кг (0,0074 ± 0,0007 %)», `3σ = 7`, перевод в проценты;
- оборудование: первые строки — из Таблицы №2 ПИ (приведены к виду «Зав. № 940289, инв. № СИ1»),
  следом всегда одни и те же строки вспомогательного оборудования (ВО) из шаблона;
- подписи: инженер-испытатель и его штамп ЭП — по ПИ (сертификат, владелец, срок действия),
  руководитель ИЛ (Д.Р. Хасянов) не меняется; дата обеих подписей — дата окончания испытаний;
- Приложение №1 начинается с новой страницы; каждое фото из ПИ — на своей странице вместе с подписью
  («Фото №N», название, диапазон компонентов). Фото увеличивается до 24×12,5 см, а если подпись
  (или строка «Конец технических записей») не помещается — уменьшается, чтобы подпись не уходила
  на следующую страницу. Поэтому «Приложение № 1 на N страницах» = числу фото;
- колонтитул: `№ {номер направления} от {дата направления}`, «Общее количество страниц» — поле Word.

## Инженеры и штампы ЭП

Встроены: С.Д. Рождественский, М.С. Свистунов (`ENGINEERS` в `converter.py`). Если в ПИ указан
другой инженер, программа предупредит и не тронет штамп. Добавить инженера без пересборки — файл
`инженеры.json` рядом с `PI_to_PZ.exe` (UTF-8):

```json
{
  "А.Б. Иванов": {
    "owner": "Иванов Андрей Борисович",
    "certificate": "0123456789abcdef",
    "valid": "с 10.11.2025 по 10.11.2026"
  }
}
```

## Настройки

В начале `converter.py`:

| Параметр | Что задаёт |
|---|---|
| `FIRST_COMPONENT_OFFSET_MIN`, `LAST_COMPONENT_OFFSET_MIN` | +30 мин к началу для компонента 1, −5 мин к окончанию для последнего |
| `SIGNATURE_DATE_SOURCE` | дата подписей: `"test_end"` (окончание испытаний) или `"pi"` (дата ПИ) |
| `WORKDAY_START`, `WORKDAY_END` | рабочий день (09:00–18:00) для многодневных испытаний вида «ДД1 с ЧЧ:ММ по ДД2 ЧЧ:ММ» |
| `HEADER_NUMBER_SOURCE` | что писать в колонтитуле: `"napravlenie"` или `"pi"` |
| `ENGINEERS` | инженеры и сертификаты ЭП |
| `PHOTO_MAX_W`, `PHOTO_MAX_H` | максимальный размер фото в приложении |

Шаблон можно заменить без пересборки: положите свой `ПЗ_template.docx` рядом с `PI_to_PZ.exe` —
программа возьмёт его вместо встроенного. Чтобы сделать шаблон из готового ПЗ:
`python tools/make_template.py ПЗ_эталон.docx ПЗ_template.docx`.

## Сборка EXE

На Windows с Python 3.11+:

```bat
build.bat
```

Скрипт ставит `lxml` и `pyinstaller` и выполняет
`pyinstaller --onefile --windowed --add-data "ПЗ_template.docx;." --name "PI_to_PZ" main.py`.
Результат — `dist\PI_to_PZ.exe`.

EXE также собирается автоматически в GitHub Actions (`.github/workflows/build-exe.yml`) при каждом push:
тесты → `build.bat` → проверка EXE на тестовом ПИ → артефакт `PI_to_PZ` во вкладке Actions.

## Запуск без EXE

```bash
pip install lxml
python main.py                                   # окно
python converter.py ПИ.docx [шаблон] [папка]     # из командной строки
```

## Тесты

```bash
python -m unittest discover -s tests -v
```

- `tests/fixtures/ПИ_2609082_от_15.09.2026.docx` — настоящий ПИ (фото уменьшены), результат сверяется
  с эталонным ПЗ 46ТР-НИ (`pz_2609082_expected.json`): все абзацы до Приложения №1 и штампы ЭП;
- `tests/fixtures/pi_2610101.json` + `tests/make_sample_pi.py` — ПИ 2610101 на 173 компонента
  (другой инженер, 12 фото), а также многодневные испытания, давление с двумя знаками, ПИ без фото,
  разрыв таблицы компонентов, неизвестный инженер.
